Verdict Circuit

A claim goes in. A frozen on-chain TapeOut circuit on X Layer mainnet returns the verdict. No trusted party, no server in the middle — anyone can re-run the same call and get the same answer.

1 · Make a claim

Try one in a single tap — the form fills in and the circuit answers:

The circuit only sees two 16-bit numbers (0–65535). Your raw values are scaled into that range first — the scale is printed on the proof card, so anyone can check the verdict from the raw numbers alone. The call is a free eth_call on X Layer mainnet (chain 196); no wallet, no gas, no transaction.

2 · Proof card

Logging writes to the public VerdictLog contract on X Layer testnet (chain 1952) — it needs a wallet (MetaMask or similar) connected to testnet. The log stores only the claim hash + verdict; the verdict itself is computed by the mainnet circuit, never by the log contract.

3 · Verdict log (public, X Layer testnet)

Recent logged verdicts — the last ~10,000 blocks (about 3 hours at 1-second blocks), read straight from the VerdictLog contract (). Older verdicts are not listed here: they stay countable via the contract's count() and checkable one by one on the explorer. A full history list would need an indexer (a server watching events); this page is static with no backend, so the recent window is the design, not a gap.

How it works

  1. Your claim is scaled into two 16-bit numbers and packed into one 32-bit input: observed | (threshold << 16), 4 bytes little-endian.
  2. The app calls eval(7, input) on processor 0xf9bbdc7f678eb3a49d338ffacdaad9339de50a0f (cpu 400, circuit #7, 114 gates, a 16-bit unsigned comparator) via a free eth_call.
  3. The circuit returns 1 iff observed ≥ threshold. The proof card records the claim, both scaled inputs, the scale, the circuit address + #ID, the block number and the output — everything needed to re-run it.
  4. Optional: the verdict is logged (claim hash + 0/1) in the VerdictLog contract on X Layer testnet, so verdicts are timestamped and auditable.
